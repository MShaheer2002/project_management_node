Everyone has one **role** in each workspace. The role decides what they can do there.

| Role | What they can do |
|---|---|
| **Owner** | Everything, including billing, deleting the workspace and the invite domain rule. There is exactly one owner. |
| **Admin** | Everything except billing changes and deleting the workspace: members, invites, settings, labels, templates, integrations, documents and API keys. Can view billing. |
| **Member** | Create and edit issues, projects, teams, cycles and roadmap items, comment and upload files. |
| **Guest** | View what they're given access to and comment. Can't create issues, projects, teams or cycles. |

## Common actions by role

| Action | Owner | Admin | Member | Guest |
|---|---|---|---|---|
| View and comment on issues | Yes | Yes | Yes | Yes |
| Create and edit issues | Yes | Yes | Yes | No |
| Delete issues | Yes | Yes | No | No |
| Create projects, teams, cycles | Yes | Yes | Yes | No |
| Delete projects and teams | Yes | Yes | No | No |
| Create departments, labels, templates | Yes | Yes | No | No |
| Invite and remove members, change roles | Yes | Yes | No | No |
| Workspace settings and integrations | Yes | Yes | No | No |
| View billing | Yes | Yes | No | No |
| Change plan and payment cards | Yes | No | No | No |
| Delete the workspace | Yes | No | No | No |

## Leads and heads

Some people get extra control over one thing:

- A **project lead** can edit and archive their project, manage its members and change its workflow.
- A **team lead** can edit their team and manage its members.
- A **department head** can edit their department and manage its members.

This works even if their workspace role is Member.

## Plans
